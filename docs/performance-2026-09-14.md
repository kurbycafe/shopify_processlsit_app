# 페이지 속도 개선 — 2026-09-14

## 변경

- 공통 app loader에서 웹훅 등록 확인과 고객 요청/알림 처리의 대기를 제거했다. 인증은 계속 수행한다. 기존 보호된 `/api/check-cancellations` 요청에서 두 작업을 수행하며 첫 화면이 열린 뒤 즉시 요청한다. 서버 작업은 해당 HTTP 요청 안에서 끝까지 await한다.
- 고객 요청 확인은 기존 25초 주기를 유지한다. 비활성 탭/오프라인에서는 멈추고 복귀하면 다시 확인한다. 동일 서버 인스턴스에서 같은 shop의 중복 요청은 합치며, 확인 결과는 20초만 재사용한다. 웹훅 등록 상태는 shop+callback URL별 1시간 재사용한다. 주문/재고/고객 상세 데이터는 이 캐시에 넣지 않는다. 서버 인스턴스 간 공유 캐시는 아니다.
- 대시보드의 Shopify, Odoo, DB 조회 7개를 병렬 실행한다. 조회 필터와 반환 필드는 유지한다.
- 고객 요청 확인의 기존 알림 여부 조회는 최대 25회 개별 DB 조회에서 shop 필터가 있는 일괄 조회 1회로 변경했다.
- DB 구조 준비 여부는 최초 접근 시 카탈로그 조회 1회로 확인한다. 기존 테이블/컬럼/인덱스 64개 조건이 모두 충족되면 기존 35개 DDL 작업을 생략한다. 누락되면 기존 보완 절차를 실행하며, 오류 시 다음 요청에서 재시도할 수 있게 한다.
- 재고 보고서 XLSX 모듈을 버튼 클릭 시 동적 로드한다. 로딩 상태와 실패 재시도를 제공한다.

- 로컬 production build 통과. 마지막 helper 추출은 배포 빌드에서 추가 확인.

## 검증 범위와 후속 병목

로그인된 Shopify 화면의 전후 TTFB/LCP 수치는 아직 측정하지 않았다. 인증 없는 공개 API 응답 시간으로 관리자 페이지가 빨라졌다고 주장하지 않는다. 실제 고객 요청 메일 발송이나 주문/재고 변경을 검증 목적으로 실행하지 않았다.

처리중 리스트의 전체 주문 조회와 월별 재고 보고서의 전체 상품/세율 계산은 여전히 데이터 규모에 비례하는 작업이다. 정확한 인쇄/집계 결과를 유지하기 위해 이번 변경에서는 데이터를 잘라내거나 오래된 재고 캐시를 제공하지 않았다. 대량 데이터에서의 추가 개선은 실제 조회 시간을 측정한 뒤 비동기 보고서 생성 등의 방식으로 진행해야 한다.
