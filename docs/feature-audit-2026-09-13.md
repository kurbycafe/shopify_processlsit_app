# 기존 기능 점검 — 2026-09-13

전체 기능의 실운영 검증 완료 상태는 아니다. 자동 테스트와 빌드 통과는 실제 고객 계정의 로그인, 주문, 결제, 이메일 수신 완료를 증명하지 않는다.

## 이번 수정

| 기능 | 발견한 문제 | 수정 내용 |
| --- | --- | --- |
| 재주문 | 상품명 추측 매칭, 임시 variant ID, 과거 가격 사용 | 주문의 정확한 variant ID로 현재 상품 조회. 현재 재고와 이미 담긴 수량을 반영하고 구매 불가 수량은 안내 |
| 프로필 | 서버 저장 실패도 성공 표시, OAuth 토큰을 Storefront API에 사용 | Customer Account customerUpdate 사용. 서버 저장 성공 때만 이름 반영. 이메일·전화 변경은 고객 계정으로 연결 |
| 배송지 | 구형 인증 API, 기본 주소는 로컬만 변경 | Customer Account 조회/생성/수정/삭제 및 기본 주소 API 연결. 도로명·상세주소·도시·우편번호·국가 필드 구분. 조회 오류/재시도, 계정 변경 시 이전 응답 차단 |
| 재입고 알림 | 기기 내부 배열만 추가하고 완료 표시 | POST /api/customer/v1/restock-subscription으로 기존 서버 구독 저장. 저장 실패는 오류 표시. 서버가 공개 상품과 SKU 검증 |
| 컨테이너 상태 | 항상 SCHEDULED 표시, 같은 RECEIVED 요청도 알림 재실행 | 저장된 상태 표시, 상태 변경 확인, 동시 요청 잠금, 같은 상태 재요청은 변경·알림 생략 |
| 입고 기록 | PO 재조회 시 receivedQty를 0으로 덮어쓸 수 있음 | 입고 완료 또는 수령 수량이 있는 경우 기존 품목 기록 보존 |

## 검증

- Processlist 자동 테스트 32개 통과.
- 모바일 자동 테스트 37개 통과: 결제 복구/세션, 조회/폴링, 재주문, 프로필 저장 실패, 구독 오류 전파 포함.
- 두 프로젝트의 production build 통과.
- 운영 배포 후보: dpl_3EKy4oRThw5txhSyxyRd5rRzfR2Y.
- 기존 운영 도메인으로 승격 완료. Android assembleRelease 성공, iOS 웹 자산 복사 완료(iOS 네이티브 빌드 미실행). Android 도구체인의 기존 Kotlin 메타데이터 및 SDK 호환성 경고가 남아 있음.
- 후보 API: 비로그인 주문 401, 구독 GET 405, 잘못된 이메일 POST 400, 공지 200 확인.
- 검증 과정에서 실제 고객의 주소/프로필 변경, 주문/결제/재고 변경, 이메일 발송은 수행하지 않음.

## 남은 실제 운영 검증 및 구현

1. 실제 고객 계정으로 로그인 → 본인 주문/검수 확인 → 재주문 → 결제까지 검증.
2. 실제 Customer Account 앱의 쓰기 권한으로 배송지 및 이름 변경 검증. 공식 API 스키마에 맞춘 코드이나 실제 계정 쓰기 테스트는 미실행.
3. 재입고 구독 저장 → 재고 이벤트/관리자 입고 완료 → 이메일 수신까지 검증. 이번 smoke test는 저장 없는 유효성 검증만 수행.
4. 출석·룰렛·리뷰 보상은 현재 로컬 처리이며 실제 포인트/쿠폰 지급 서비스가 확인되지 않음. 운영 서비스와 지급 정책 확인 필요.
5. 사진 리뷰 저장/사진 업로드 및 게시 관리 연결 필요. 현재 로컬 게시물을 실제 게시·포인트 지급 완료로 취급하면 안 됨.
6. 일부 문의·반품·사업자 문의는 이메일 작성 또는 로컬 기록까지만 처리. 서버 접수번호·처리 상태·실제 반품 결과와 연결 필요.
7. 탈퇴 요청과 실제 계정 삭제를 구분하고 처리 결과를 확인하는 흐름 필요.
8. 재입고 알림은 이미 완료된 상태 재전송으로 다시 발송하지 않음. 저장 후 알림 실패는 별도 경고 및 기존 알림 관리에서 처리. 보장된 이벤트 전달(outbox)은 추가 과제.
9. Storefront fallback 주문 경로에는 모바일 전용 주문 API와 같은 상품 페이지네이션을 아직 제공하지 않음. 운영 모바일 설정은 Processlist 경로를 사용.
