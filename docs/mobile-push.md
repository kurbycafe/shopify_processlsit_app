# DAWAYO 모바일 푸시 운영

2026-10-26 기준 소스 구현 완료. 빌드, 배포, 운영 환경변수 변경, 실제 푸시 발송은 실행하지 않았다.

## 계정과 동의

- 로그인한 Shopify Customer ID와 설치 기기를 연결한다. 이메일만으로 주문 또는 고객 기기를 연결하지 않는다.
- 전체 알림과 각 항목(주문/배송, 고객센터 답변, 신청 상품 재입고, 이벤트, 마케팅)을 별도로 저장한다. 신규 항목은 기본적으로 동의하지 않은 상태다.
- 저장된 전체 알림 동의와 OS 권한이 있으면 로그인 복원, 앱 활성화, 네트워크 복귀 및 토큰 변경 때 자동 등록한다. 자동 처리에서는 OS 권한 창을 띄우지 않는다. 사용자가 전체 알림을 켜거나 등록을 다시 확인할 때 권한을 요청한다.
- 등록 후에는 앱을 열어 두거나 알림마다 다시 로그인할 필요가 없다. 로그아웃, 계정 전환, 동의 철회 시 연결을 해제한다. 오프라인 해제 요청은 기기에 보존하여 다음 연결 때 먼저 처리한다.
- 휴대전화 잠금 화면에는 일반 안내만 표시한다. 주문·문의의 상세 내용은 현재 로그인한 계정으로 알림함에서 조회하며 계정이 다르면 접근을 차단한다.
- 비회원 주문은 기존 주문 확인 이메일을 이용한다. 해당 주문이 Shopify 고객 계정에 연결되고 그 계정으로 로그인한 기기가 등록되어야 계정 푸시 대상이 된다.

## 구현한 흐름

- 검증된 Shopify 웹훅으로 주문 생성·결제·취소·배송 시작·배송 완료 알림을 적재한다.
- 고객센터 답변과 로그인 고객이 신청한 상품의 재입고 알림을 적재한다.
- 관리자 메뉴에서 이벤트/마케팅 알림을 미리보기 후 예약하거나 특정 고객에게 시험 발송하도록 적재할 수 있다.
- 앱 헤더 알림함에 읽음 상태, 미확인 개수, 페이지 조회를 제공한다. 알림을 누르면 소유권을 확인한 주문 상세·문의·상품으로 이동한다.
- 혜택 알림에는 지정 시간대의 야간 제한을 적용한다. 주문·답변 알림은 야간 제한을 적용하지 않는다.
- 발송 직전에 동의와 기기 연결을 다시 확인한다. 중복 이벤트·동시 작업자·토큰 변경·계정 전환을 처리하고 만료 토큰을 비활성화한다.
- `SENT`는 Firebase가 요청을 수락했다는 뜻이며 실제 단말 수신 확인이 아니다. 결과가 불명확한 발송은 `UNKNOWN`으로 두며 자동 재전송하지 않는다. 관리자의 별도 확인 후 재시도한다.
- 기존 고객 요청 JSON 저장 구조와 인덱스를 사용한다. 새 테이블이나 DB 마이그레이션을 추가하지 않았다.

## 배포 전 운영 설정

1. 서버 환경에 `FIREBASE_PROJECT_ID=dawayo-f8170`을 설정하고 `FIREBASE_SERVICE_ACCOUNT_JSON` 또는 적절한 `GOOGLE_APPLICATION_CREDENTIALS`를 구성한다. 서비스 계정에는 필요한 Firebase 발송 권한만 부여한다. 비밀키는 소스·앱·채팅에 넣지 않는다. Android의 `google-services.json`은 서버 발송 자격 증명이 아니다.
2. 서버와 작업자에 동일한 무작위 `PUSH_WORKER_SECRET`을 설정한다. 최소 32자여야 한다.
3. 소스에 추가한 Shopify `read_fulfillments`, `read_inventory` 범위의 승인을 적용하고 웹훅 등록을 확인한다. 구성 검증 CLI는 현재 로그인 계정의 조직 접근 권한 부족(403)으로 완료하지 못했다. 로컬 TOML 문법과 GraphQL 스키마 검사는 별도로 통과했다.
4. 서버를 먼저 배포한다. 새 클라이언트는 서버의 푸시 프로토콜 버전 2를 확인하며 이전 서버를 성공으로 처리하지 않는다.
5. 작업자 요청 주소는 `https://process-list-beryl.vercel.app/api/mobile-push-dispatch`이다. `Authorization: Bearer <PUSH_WORKER_SECRET>`으로만 호출한다. URL 쿼리에 비밀키를 넣지 않는다.
6. 제공한 GitHub Actions 스케줄을 사용할 경우 저장소 변수 `MOBILE_PUSH_WORKER_URL`, `MOBILE_PUSH_WORKER_ENABLED=true`와 저장소 비밀 `PUSH_WORKER_SECRET`을 설정한다. 워크플로는 5분 간격이며 활성화 변수 없이는 실행하지 않는다. GitHub 스케줄은 정확한 발송 시각을 보장하지 않으므로 더 엄격한 지연 요구에는 운영 스케줄러를 사용한다.
7. Android 변경 사항을 포함한 새 앱을 배포하고 아래 단말 검증을 완료한다. 현재 설치본에는 소스 수정이 자동 반영되지 않는다.

웹훅 등록 목록에는 기존 주문 이벤트와 신규 fulfillment 생성/갱신/이벤트 및 inventory 갱신을 포함한 9개 항목이 있다. Shopify 관리자에서 실제 구독 상태를 확인해야 한다.

## 검증 근거와 남은 확인

- 앱 Node 회귀 검사 152개, 기본 검사 46개, 서버 검사 310개 통과. 앱 및 서버 린트 통과.
- 새 관리자 JSX 변환, Android Manifest 및 아이콘 XML, Shopify TOML 문법 검사 통과.
- 주문 조회 Admin GraphQL 및 Customer Account GraphQL을 2026-10 스키마로 검증했다.
- 외부 Polaris App Home v1 컴포넌트 검증기는 이 저장소의 기존 React Polaris 구성을 해석하지 못했다. 이를 통과로 판정하지 않았다. 저장소 자체 린트와 JSX 변환은 통과했다.
- 로컬 웹의 비로그인 알림함·설정 화면을 확인했다. OS 권한, Firebase 실제 발송, 실제 주문 웹훅과 단말 수신은 이 검사에 포함되지 않는다.

- 허용/거절/OS 설정에서 권한 철회 후 자동 등록 상태와 서버 기기 상태.

- 로그아웃, 오프라인 로그아웃, 다른 계정 로그인 및 늦게 완료된 이전 등록 요청.
- 실제 시험 주문의 결제·취소·배송 이벤트와 정확한 주문 상세 이동.
- 고객센터 답변 및 신청 상품 재입고의 실제 발송과 수신 내역 대조.
