# 재입고 알림 발송 기록 확인

메일 제공자가 전송을 접수하면 외부 전송은 완료된 것으로 취급한다. 이후 DB의 완료 기록 저장만 최대 세 번 재시도한다. 완료 기록 오류를 전송 실패로 바꾸거나 같은 함수에서 메일을 다시 전송하지 않는다.

세 번의 완료 기록 저장이 모두 실패하면 가능한 경우 `DELIVERED_UNCONFIRMED` 상태를 남긴다. 관리 화면의 **발송됨 · 기록 확인 필요** 필터와 경고에서 확인할 수 있다. 이 상태는 자동 재시도·수동 선택 발송 대상에서 제외된다. 메일 제공자의 수신처와 발송 시각별 기록을 대조한 뒤 기존 운영 데이터 정정 절차로 처리한다. 확인 전에 `PENDING`이나 `FAILED`로 되돌려 재발송하지 않는다.

DB 전체가 계속 중단되어 이 확인 필요 상태조차 저장할 수 없으면 기존 `PROCESSING` 기록만 남을 수 있다. 서버 로그와 호출 응답에 수동 확인 경고를 남기지만, 저장하지 못한 전송 결과를 다른 서버가 알 수는 없다. 만료된 선점의 자동 재시도 전에 해당 시간대의 메일 제공자 기록을 확인해야 한다. 제공자의 접수 직후 프로세스가 중단된 경우도 같은 한계가 있다. 제공자 멱등성 키와 영속 outbox가 없는 현재 구성에서 이 중복 가능성을 완전히 제거하지는 않는다.

고객의 구독 취소는 대기·발송 실패·발송 중 상태를 취소하며, 발송 직전과 푸시 실패 후 이메일 대체 전송 직전에도 선점 상태를 다시 확인한다. 이미 외부 제공자에 전달 중인 요청을 되돌리지는 못한다.
